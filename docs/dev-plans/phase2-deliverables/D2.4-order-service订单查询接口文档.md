# D2.4 order-service 订单批量查询接口文档

| 项 | 内容 |
|---|---|
| 所属 | Phase 2 / T2.11（附录 B 唯一业务服务改造点） |
| 服务 | order-service（`VoucherOrderController`） |
| 调用方 | agent-service（`OrderFeignClient`，Feign 超时 2s，PRD 4.1） |
| 版本 | v1.0（2026-09-01） |

## 1. 接口定义

```
GET /voucher-order/my
```

**鉴权（授权红线，PRD 4.2）**

- 请求头 `Authorization: <satoken>`（agent-service 经 `FeignAuthConfig` 透传当前用户 token）
- `userId` 从登录态（Sa-Token 会话）强制注入，**接口不接受 userId 参数**——即使 LLM/前端传入归属参数也会被忽略
- 未登录返回 `Result.fail("未登录，请先登录")`

**查询参数（均可空）**

| 参数 | 类型 | 说明 |
|---|---|---|
| orderId | Long | 聚焦某订单（用户点选订单卡片后写入会话焦点） |
| status | Integer | 1未支付 2已支付 3已核销 4已取消 5退款中 6已退款 |
| days | Integer | 最近 N 天（按 create_time 过滤，>0 生效） |
| page | Integer | 页码，从 1 开始，默认 1 |
| size | Integer | 每页条数，默认 5，上限 20 |

## 2. 响应

```json
{
  "success": true,
  "data": [
    {
      "id": 123456789,             // 订单号（agent 侧映射为 orderId）
      "userId": 1,
      "voucherId": 10,
      "voucherTitle": "尾款人专享券", // 联查 tb_voucher；联查失败时为 null（降级不阻塞）
      "payValue": 1000,            // 支付金额（分）
      "actualValue": 500,          // 抵扣金额（分）
      "status": 2,
      "createTime": "2026-09-01T10:00:00",  // ISO-8601，agent 侧解析进订单卡片
      "payTime": null, "useTime": null, "refundTime": null
    }
  ],
  "total": 12,        // 命中总数（分页用）
  "errorMsg": null
}
```

- 排序：create_time 倒序（最新订单在前）
- 分页：MyBatis Plus 无分页插件，实现为 count + `LIMIT s OFFSET (p-1)*s`

## 3. 边界与错误语义（与 PRD FR-05 对齐）

| 场景 | 行为 |
|---|---|
| 越权查询（orderId 属他人） | userId 过滤条件恒在 → 返回空列表，**不泄露订单存在性**（FR-05 验收 5） |
| voucher-service 联查失败 | 降级仅返回订单字段，log.warn 记录，不影响订单返回 |
| agent 侧 Feign 超时（2s） | agent 侧走 ReAct 连败计数 → 引导建单/转人工（FR-05 边界） |

## 4. 验收对照（Phase 2 §5）

- 验收 12（对拍一致性）：查询逻辑为数据库直查（非 LLM 参与），一致性由对拍用例保障（MS1 演示脚本步骤 6，全量 100 条在 Phase 3 T3.14 补齐）
- 验收 13（越权拦截）：userId 登录态强制注入，结构性杜绝参数篡改
