## 1. 阶段目标

1. 交付 P0 写操作与人机协同链路：FR-08（退款申请，确认卡片 + 后端二次校验 + 幂等）、FR-09（工单创建与自动路由）、FR-10（转人工与上下文移交）。
2. 交付 FR-11（安全风控）：频控、注入防护（输入检测/prompt 加固/输出过滤三层）、AI 标识、数据红线全部落地，注入攻击集 30 条拦截率 100%。
3. 完成 P0 全量功能（FR-01~FR-11）的服务间集成联调（order/voucher/shop/rag/social/user 五个依赖服务 + gateway + MQ）。
4. 达成 MS2 退出标准：全部 P0 功能的自动化用例（对拍/幂等/越权/注入）通过率 100%。

```
退款线：T4.1 确认卡片机制 → T4.2 退款编排 → T4.3 二次校验 → T4.4 幂等/越权 → T4.5 联动建单
                                                                            ↓
工单线：T4.6 create_ticket（独立可并行）→ T4.7 路由与 MQ 通知 ───────────────┘
                                                                            ↓
转人工线：T4.8 触发器（依赖 Phase 3 澄清/工具失败事件）→ T4.9 卡片与移交包
                                                                    ↓（无人值守建单复用 T4.6）
安全线：T4.10 网关频控 / T4.11 输入检测 / T4.12 输出过滤 / T4.13 数据红线（四者独立并行）
                                                                    ↓
容灾线：T4.14 熔断与降级（依赖 T4.8 的转人工触发器就绪）
                                                                    ↓
收口：T4.15 全链路联调（依赖以上全部）→ T4.16 P0 用例全集 → MS2 退出

关键路径：T4.1 → T4.2 → T4.3 → T4.4 → T4.5 → T4.6 → T4.15 → T4.16
```

- 退款线 / 工单线 / 安全线三条可并行推进；T4.5 依赖 T4.6 就绪。
- T4.14 依赖 T4.8（工具连续失败的转人工触发）。
- T4.16 为 MS2 退出门禁，未通过不得进入 Phase 5。

## 5. 验收标准（对齐 PRD 条目级验收标准）

**FR-08 验收标准（3.8）**
1. 确认操作幂等：并发重复确认 100% 仅生效一次（自动化测试，含并发 10 次确认仅 1 条退款记录压测用例）。
2. 越权（篡改 actionId/订单号）100% 拦截。
3. 退款申请提交成功率 ≥ 99%（排除用户主动取消）。
4. 从表达退款意图到卡片出现 P90 ≤ 8s。

**FR-09 验收标准（3.9）**
5. 工单分类准确率 ≥ 90%（人工抽检 100 单）。
6. 涉资金问题 priority=高 覆盖率 100%（规则测试）。
7. 建单失败率 < 0.5%，失败场景 100% 有降级出路（转人工），不静默丢失诉求。
8. 工单号唯一且可查询（FR-13 查询能力在 Phase 5，本阶段保证数据可查）。

**FR-10 验收标准（3.10）**
9. 四类触发条件各自 100% 触发（各 20 条用例）。
10. 移交包摘要"身份/诉求/已查事实/待解决"四要素完整率 ≥ 95%（人工抽检）。
11. 触发转人工后 Agent 零后续输出（日志验证）。

**FR-11 验收标准（3.11）**
12. 注入攻击测试集（30 条，中英文/变体）拦截率 100%。
13. 频控边界：11 QPS 触发限流、9 QPS 不触发。
14. 敏感词热更新 1 分钟内生效。
15. 全部会话与拦截事件审计表 100% 留痕。

**MS2 退出标准（第 7 章）**
16. 全部 P0 功能的自动化用例（对拍/幂等/越权/注入）通过率 100%。

## 6. 潜在风险与应对措施

| # | 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|---|
| P4-R1 | 退款误执行（重复退款/越权退款，R4） | 低 | 高 | 双闸门缺一不可：确认卡片 + 后端二次校验（归属/状态/幂等）；actionId 一次性消费；每日对账脚本核对退款数与确认数（本阶段搭建） |
| P4-R2 | Prompt 注入防护被绕过（R3） | 中 | 高 | 三层防护叠加（输入检测 + prompt 加固 + 输出过滤）；30 条攻击用例 + 变体扩充至 50 条回归；命中即审计留痕；误伤走建单申诉通道 |
| P4-R3 | 结构化输出不稳定影响卡片/工单参数生成（R2 蔓延至写操作） | 中 | 中 | 复用 Phase 3 T3.2 解析组件；写操作参数必须通过 schema 校验才允许生成卡片；LLM 参数仅作候选，二次校验为最终裁决 |
| P4-R4 | 幂等实现缺陷（并发窗口漏单） | 低 | 高 | actionId 数据库唯一约束 + 状态机原子流转；并发压测（10 并发确认）作为硬门禁用例 |
| P4-R5 | MQ 通知链路（social-service 站内信）延期 | 中 | 中 | MQ 消息先落 agent_ticket 路由状态，通知消费端可后补（工单创建与通知解耦）；站内信未就绪时工单仍可在 Phase 5 工作台查看 |
| P4-R6 | 情绪识别误判导致误转人工（R8） | 中 | 低 | 初版仅词典 + 规则，高置信才触发；误判反馈记录进入 Phase 5 周迭代 |
| P4-R7 | 工具调用放大上游服务延迟（R6） | 中 | 高 | Feign 2s 超时 + 单次重试；网关 agent 路由独立限流 10 QPS/用户；Sentinel 熔断快速失败走降级；联调时做上游故障注入演练 |
| P4-R8 | P0 范围蔓延（提前做 P2 工作台，R9） | 高 | 中 | P2 工作台严格冻结至 MS4 发布后；人工接管先以模拟坐席（后台直连 SSE role=human）验证 |
