# D1.3 数据模型设计文档（agent_service 库）

| 项 | 内容 |
|---|---|
| 版本 | v1.0（Phase 1 交付物） |
| 数据库 | MySQL（既有实例），独立 schema：`agent_service` |
| ORM | MyBatis Plus 3.5.6（项目统一） |
| 配套 DDL | `agent_service_ddl.sql`（同目录，可直接执行） |

设计原则：① 严格对齐 PRD 6.1 四张表 + 三个补充字段，不添加 PRD 之外的业务表；② 审计表仅追加（无 UPDATE/DELETE，应用层 + DB 权限双约束）；③ 所有表含 `create_time/update_time`，软删不采用（审计不可删）；④ 字符集 utf8mb4。

---

## 1. ER 关系

```
agent_session 1 ──── n agent_tool_call   （一次会话多次工具调用）
agent_session 1 ──── n agent_task        （确认卡片/退款申请挂会话）
agent_session 1 ──── n agent_ticket      （会话可产生多张工单）
agent_task    n ──── 1 agent_ticket      （退款确认通过 → 联动建复核工单，task.ticket_id）
```

---

## 2. 表设计

### 2.1 agent_session（会话主表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, 雪花ID | sessionId |
| user_id | BIGINT | NOT NULL, IDX | 归属用户（与 Sa-Token 强绑定） |
| module | VARCHAR(8) | NOT NULL, DEFAULT 'M5' | 模块标识（PRD 6.1） |
| status | VARCHAR(16) | NOT NULL | ACTIVE / CLOSED / TRANSFERRED |
| entry | VARCHAR(16) | NOT NULL | my / order_detail / voucher_detail（埋点口径） |
| context_json | JSON | NULL | 入口预注入 {orderId\|voucherId\|shopId} |
| summary | VARCHAR(1024) | NULL | 第 11 轮起的 LLM 压缩摘要（≤512 字） |
| flow_state | VARCHAR(16) | NOT NULL DEFAULT 'IDLE' | IDLE/CLARIFYING/REFUNDING/COMPLAINING/TRANSFERRING（D1.2 §4 状态机） |
| rating | TINYINT | NULL | 1-5（PRD 补充字段；NULL=未评价） |
| rating_tags | VARCHAR(128) | NULL | 不满意多选标签，逗号分隔 |
| transfer_reason | VARCHAR(32) | NULL | HUMAN_DEMAND / TOOL_FAIL / CLARIFY_EXCEED / NEGATIVE_EMOTION（PRD 补充字段） |
| token_cost | DECIMAL(10,4) | NOT NULL DEFAULT 0 | 会话累计成本（元） |
| msg_count | INT | NOT NULL DEFAULT 0 | 单会话消息数（频控用，上限 100） |
| snapshot_uri | VARCHAR(256) | NULL | 回放快照存储引用（Phase 5 FR-13 使用） |
| close_reason | VARCHAR(16) | NULL | USER / TIMEOUT / TRANSFER（关闭归因） |
| create_time / update_time | DATETIME | NOT NULL | |

索引：`idx_user_status(user_id, status)`（并发会话检测）、`idx_user_time(user_id, create_time)`（FR-13 列表）、`idx_status_close(status, update_time)`（30 分钟超时扫描）。

### 2.2 agent_tool_call（工具调用审计，**仅追加**）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | PK |
| session_id | BIGINT | NOT NULL, IDX |
| user_id | BIGINT | NOT NULL |
| tool_name | VARCHAR(64) | NOT NULL（query_my_orders / query_voucher / ...） |
| args_json | JSON | 入参（LLM 提供部分 + 服务端注入部分，脱敏后落库） |
| result_summary | VARCHAR(1024) | 结果摘要（脱敏后） |
| success | TINYINT | 1/0 |
| latency_ms | INT | 耗时 |
| trace_id | VARCHAR(64) | 全链路追踪（WebFlux/MDC 贯通 SSE 异步线程） |
| step_no | TINYINT | ReAct 第几步（1-8） |
| error_code | VARCHAR(32) | NULL |
| create_time | DATETIME | |

索引：`idx_session(session_id, create_time)`。**不可篡改实现**：不给应用账号 UPDATE/DELETE 权限（DDL 内含 GRANT 注释说明），MyBatis 仅提供 insert/select。

### 2.3 agent_task（确认卡片/退款申请）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | PK |
| session_id | BIGINT | NOT NULL, IDX |
| user_id | BIGINT | NOT NULL |
| task_type | VARCHAR(32) | REFUND_REQUEST（预留扩展） |
| status | VARCHAR(20) | PENDING_CONFIRM / ADOPTED / REJECTED / EXPIRED |
| action_id | VARCHAR(64) | **唯一约束**，幂等凭证（一次性消费） |
| payload_json | JSON | 卡片内容（订单摘要/原因选项/预计时效） |
| confirm_reason | VARCHAR(256) | NULL，用户选择的退款原因 |
| expire_time | DATETIME | 生成时间 + 10 分钟 |
| ticket_id | BIGINT | NULL，ADOPTED 后联动的复核工单 |
| confirm_time | DATETIME | NULL |
| create_time / update_time | DATETIME | |

索引：`uk_action_id`（唯一）、`idx_session_status(session_id, status)`。
幂等设计（KD-7）：确认接口执行 `UPDATE agent_task SET status='ADOPTED', confirm_time=... WHERE action_id=? AND status='PENDING_CONFIRM' AND expire_time>NOW()`，受影响行数=1 才继续；并发重复确认仅一条生效。

### 2.4 agent_ticket（工单）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | PK |
| ticket_no | VARCHAR(24) | **唯一约束**，TK+yyyyMMdd+6 位序号（Redis INCR 生成） |
| session_id | BIGINT | NOT NULL, IDX |
| user_id | BIGINT | NOT NULL |
| category | VARCHAR(16) | ORDER / VOUCHER / MERCHANT_SERVICE / ACCOUNT_SECURITY / OTHER |
| priority | VARCHAR(8) | HIGH / MEDIUM / LOW（涉资金=高，普通=中，建议=低） |
| summary | VARCHAR(256) | LLM ≤200 字客观摘要（失败时规则模板兜底） |
| refs_json | JSON | {orderId?, voucherId?, shopId?} |
| dedup_key | VARCHAR(64) | PRD 补充字段：MD5(category + sorted(refs) + session_id)，**唯一约束**实现会话内去重 |
| status | VARCHAR(16) | OPEN / ROUTED / RESOLVED |
| assignee_group | VARCHAR(16) | ORDER_GROUP / MARKETING_GROUP / MERCHANT_GROUP / SECURITY_GROUP |
| expected_sla | VARCHAR(8) | 4h / 24h / 72h（与 priority 绑定，写入时固化） |
| notify_status | VARCHAR(16) | PENDING / SENT / FAILED（MQ 通知结果） |
| handle_result | VARCHAR(512) | NULL，RESOLVED 时的处理备注（P2 工作台填写） |
| resolve_time | DATETIME | NULL |
| create_time / update_time | DATETIME | |

索引：`uk_dedup_key`、`uk_ticket_no`、`idx_group_priority_status(assignee_group, priority, status)`（P2 工作台查询预留）、`idx_user(user_id)`（我的工单）。

状态机（合法跳转，应用层枚举校验）：`OPEN → ROUTED → RESOLVED`；其余跳转 100% 拒绝并告警（对应 FR-14 验收"非法状态跳转 100% 拦截"）。

## 3. 补充字段核对（PRD 6.1 要求）

| PRD 补充字段 | 落点 | 状态 |
|---|---|---|
| agent_session.rating TINYINT（1-5 可空） | §2.1 rating | ✅ |
| agent_session.transfer_reason VARCHAR(32) | §2.1 transfer_reason | ✅ |
| agent_ticket.dedup_key VARCHAR(64) | §2.4 dedup_key（唯一约束） | ✅ |

## 4. 数据生命周期

| 数据 | 保留策略 | 依据 |
|---|---|---|
| agent_session（含回放快照） | 90 天在线 → 归档表（`*_archive`，结构一致）→ 1 年后删除 | 4.2 会话数据保留 90 天 |
| agent_tool_call | 90 天 → 归档（审计追溯要求，延长至 1 年） | 4.2 审计 |
| agent_ticket | 长期保留（业务追溯），不归档 | — |
| Redis 会话键 | CLOSED 即删 + 30min TTL 双保险 | FR-02 |

归档任务：Phase 5 T5.3 一并实现（每日调度，LOW 优先级），本阶段仅冻结表结构兼容归档（无外键、含 create_time）。

## 5. 开放问题

- `agent_session.snapshot_uri` 的快照介质（Redis JSON / MinIO / MySQL JSON 列）在 Phase 5 T5.3 细化，本版仅预留字段。
- 工单号并发段（Redis INCR 按日重置）的持久化恢复策略在 Phase 4 T4.7 实现时细化，本版仅定义号段格式。
