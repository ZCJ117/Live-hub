### 1.2 明确不做（Non-goals 重申）

评审确认 PRD 1.5 的 5 项非目标为硬边界，任何新想法一律进入 P2 备忘录，不进入本期：
不做站外渠道；不做多租户/开放 API；不做语音与数字人；不做主动营销推送；不自研/微调模型（仅 OpenAI 协议调用 GLM-5 / glm-4-flash，保持可替换）。

### 1.3 关键技术决策

| # | 决策 | 依据 |
|---|---|---|
| KD-1 | agent-service 为新独立微服务，纳入根 pom modules，命名 `agent-service`，端口 **8088**（8081~8087 已占用） | 现有 7 服务端口规划顺延 |
| KD-2 | SSE 基于 Spring MVC 异步 Servlet（DeferredResult / SseEmitter + 独立线程池），严禁 Tomcat 工作线程同步阻塞等待 LLM | PRD 4.1 性能设计约束 |
| KD-3 | LLM 接入层采用 OpenAI 协议兼容抽象（自研薄客户端，参照 rag-service llm 包既有实践），双模型：GLM-5（主）/ glm-4-flash（CHAT 意图分流 + 备用） | PRD 1.5 / 4.4 / R5 |
| KD-4 | 意图识别用 LLM 分类（JSON mode + schema 校验），不做独立分类模型训练 | PRD 1.5 不自研模型 + FR-03 |
| KD-5 | agent_service 数据落 MySQL（与主库同实例、独立 schema `agent_service`）；审计表仅追加 | PRD 6.1 / 4.2 |
| KD-6 | 短期记忆存 Redis（Redisson，项目统一客户端），TTL 与会话生命周期绑定 | PRD 3.2 / CLAUDE.md 技术栈 |
| KD-7 | 确认操作幂等采用 agent_task 状态机 + actionId 唯一约束 + 数据库原子更新，不引入 Seata 分布式事务（agent-service 与 order-service 间为最终一致 + 对账） | R4；Seata 仅保留给既有秒杀链路，避免事务链路扩大 |
| KD-8 | 网关新增 `agent-route`（Path=/agent/**），频控以 Gateway 全局过滤器（令牌桶）实现 | FR-11 / gateway-service application.yaml 现状 |
| KD-9 | rag-service 内部检索能力通过新增内部 API（`/internal/rag/retrieval/search`）暴露给 agent-service，不经网关、走 Nacos 服务发现直连 | 附录 B / 4.3（主链路不依赖 RAG） |
| KD-10 | 转人工本阶段为"模拟坐席"：TRANSFERRED 会话进队列，P2 工作台发布前无坐席在线一律落工单 | FR-10 / 1.4 定位 |

## 3. 评审中发现并确认的澄清项

| # | 问题 | 结论 |
|---|---|---|
| C-1 | 退款落库（REFUND_PENDING）是否需要真执行退款？ | 否。本期止步于"退款申请受理 + 复核工单"，人工复核后才产生真实退款动作；agent-service 仅写申请状态（PRD 3.8 流程第 5 步口径），因此无需 Seata |
| C-2 | 会话与工单数据是否与业务库隔离？ | 独立 schema `agent_service`，同 MySQL 实例（PRD 4.4"复用既有实例"），90 天保留 + 归档策略在 D1.3 定义 |
| C-3 | 频控计数器放哪？ | Redis + Redisson RRateLimiter/令牌桶脚本，网关层做 QPS 频控，agent-service 层做"日会话数 / 单会话消息数"业务频控（两层职责分离，见 D1.5） |
| C-4 | context 预注入的 orderId 归属校验时机？ | 建连时仅记录，首次工具调用时由工具层强制 userId 过滤兜底（永不信任前端 context，见 D1.5 §4） |
| C-5 | 情绪检测初版方案？ | 词典 + 规则（负面词命中 ≥ N 且句尾感叹/重复发送等信号），高置信才触发转人工；不做模型分类（PRD FR-10 + R8） |
