## 1. 灰度机制

### 1.1 开关与分桶

| 配置项（Nacos，动态生效） | 说明 |
|---|---|
| `agent.m5.enabled` | 总开关：false = 入口回退"留言反馈"页（前端读配置渲染）；已进行中会话不受影响，自然结束 |
| `agent.m5.traffic-percent` | 灰度流量百分比：0 → 10 → 50 → 100 |
| 分桶算法 | `hash(userId) % 100 < traffic-percent`；桶号由服务端建连时计算并返回（前端不自行判断，避免不一致） |
| 内部白名单 | 白名单 userId 列表始终放行（开发/测试/产品体验账号） |

### 1.2 灰度节奏与观察窗

| 档位 | 观察时长 | 通过标准（全满足才进下一档） | 不达标动作 |
|---|---|---|---|
| 10% | ≥ 24h | P0 缺陷 0；SSE 建连成功率 ≥ 99.5%；转人工率 ≤ 25%；无成本异常 | 回滚或修复后重计 |
| 50% | ≥ 24h | 同上 + 一次解决率趋势 ≥ 60%（观察值，非终值）+ 工具成功率 ≥ 99% | 同上 |
| 100% | 连续 7 天日报 | 1.2 目标跟踪：一次解决率 ≥ 70%、转人工率 ≤ 20%（未达标进周迭代，不回滚） | 迭代优化 |

观察窗内每日产出日报（D1.7 §6 门禁）：一次解决率 / 转人工率 / 意图准确率 / 工具成功率 / 退款确认转化 / 单会话成本 / P0 缺陷清单。

## 2. 回滚预案

### 2.1 触发条件（任一即回滚）

1. 出现 P0 缺陷（资金误执行 / 越权泄露 / 注入绕过 / 服务不可用 > 10 分钟）；
2. SSE 建连成功率 < 99% 持续 30 分钟；
3. 退款对账出现无法解释差异（R4 红线）；
4. 合规事故（敏感内容流出 / AI 标识缺失被发现）。

### 2.2 回滚操作（目标：5 分钟内完成）

```
1. Nacos 置 agent.m5.enabled=false（一键）
   → 新用户入口回退原"留言反馈"页；灰度用户新会话被拒并提示
2. gateway 侧确认 agent-route 仍可路由（保留排障通道）或直接关闭流量（二选一，预案演练时定稿）
3. 进行中会话：允许自然结束（SSE 会话关闭后资源释放）；不再产生新工单
4. 数据处置：已创建会话/工单/任务数据【保留不删】（PRD 明确要求），供事后分析与工单人工跟进
5. 通知：同步前端（入口已回退）、人工客服组（存量工单照常处理）
```

### 2.3 回滚后动作

- 24h 内出故障分析报告（根因/影响面/修复方案）；
- 修复后重新从 10% 档灰度（观察窗重计）；
- 测试集补充：故障场景用例回流 D1.7 对应测试集。

## 3. 回滚演练（Phase 5 T5.11）

- 时点：灰度 10% 档观察期内择机执行一次真实演练；
- 步骤：预发环境 + 生产只读彩排 → 生产触发 enabled=false → 度量"入口回退生效时间"（目标 ≤ 5 分钟）→ 记录演练报告后重新开启 10%；
- 演练通过标准：开关生效 ≤ 1 分钟（Nacos 推送）、前端入口回退 ≤ 5 分钟、无数据丢失、存量工单可正常查看。
