## 2. C1：order-service 新增"按 userId 批量查询订单"

**现状核实**（已查阅代码）：order-service 当前仅 `POST /voucher-order/seckill/{id}`（秒杀下单），确无按用户查询接口，与 PRD 附录 B 判断一致。

**新增接口契约**（供 order-service 评审，路径挂既有 `/order` 网关前缀风格，Feign 内部调用）：

```
GET /internal/order/list-by-user
  Headers: Authorization（Sa-Token，服务间透传校验）或内部签名
  Params:
    userId      必填   用户ID（服务端从登录态注入，不信任调用方明文）
    orderIds    可选   逗号分隔，精确过滤（FR-08 退款定位用）
    status      可选   订单状态过滤
    timeRange   可选   7d / 30d（默认 7d，对齐 FR-05 引导扩大逻辑）
    page / size 可选   分页，size 上限 50（FR-05 边界：>50 强制分页）
  Response: Result<Page<OrderBriefDTO>>
    OrderBriefDTO: { orderId, voucherId, voucherName, payValue,
                     status, statusReason?, createTime, seckillFlag }
```

**约束**：
1. 归属安全：userId 必须取自登录态/内部调用上下文，禁止"查任意 userId"裸暴露（越权红线，FR-05 验收 2）；agent-service 侧 ToolContext 再做一次 userId 注入兜底。
2. 性能：走 `user_id + create_time` 组合索引；P95 ≤ 1s（给 agent 2s Feign 超时留裕量）。
3. 越权语义：查询他人订单返回空结果集（不泄露存在性）。

**不改动**：秒杀链路、Seata 事务、MQ 消费（手术式修改，仅新增只读接口）。

## 3. C2：voucher-service 券详情补字段

既有券详情接口（Feign 可用）补充两个查询字段，用于 FR-06 两段式回答：

```
VoucherDTO 新增:
  threshold      DECIMAL   使用门槛（满 X 元可用）
  applicableScope JSON/字符串  适用范围：店铺ID列表 / 品类列表（含排除品类）
```

约束：字段缺失返回 null（agent-service 按"规则暂未录入"话术处理，**禁止**默认值编造语义）；不影响既有秒杀读路径。

## 4. C4：rag-service 新增内部检索 API

**现状核实**（已查阅 rag-service README）：现有 `/api/rag/qa/chat` 是面向终端的 SSE 问答，无纯检索 API。需新增不经网关的内部接口：

```
POST /internal/rag/retrieval/search   （Nacos 服务发现直连，网关不暴露）
  Body: { shopId, query, topK?(默认3) }
  Response: { hits: [{ content, score, source, kbId }] }
```

约束：仅做检索不生成（GLM 生成由 agent-service 自行完成）；商户级权限隔离沿用既有 kb 权限模型；agent-service 对其故障完全降级（FR-07 扩展信息不可用 → 仅结构化字段，主链路不受影响）。

## 5. C5：social-service 站内信通道（Phase 4 前就绪）

```
RocketMQ topic: agent-m5-ticket-route
  Message: { ticketNo, ticketId, userId, category, priority, assigneeGroup, expectedSla }
Consumer（social-service）: 新增站内信写入（"您的工单 TK… 已路由至 XX 组，预计 24h 内处理"）
```

约束：消费幂等（ticketNo 维度）；消费失败不阻塞工单落库（notify_status=FAILED 可重投）。
