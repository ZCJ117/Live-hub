## 1. 新增/变更接口

| 服务 | 接口 | 说明 |
|---|---|---|
| voucher-service | `GET /voucher/{id}` | 券详情（新增，D1.4 C2）；`Voucher` 实体补 `threshold`/`applicableScope` 可空字段 |
| rag-service | `POST /internal/rag/retrieval/search` | 内部检索 API（新增，D1.4 C4），Body `{shopId, query, topK?}`；KB 定位约定 `merchantId == shopId`；不经网关暴露 |
| agent-service | 无新 HTTP 接口 | 能力经既有 `POST /agent/chat` SSE 体现（Planner 分流 + 新工具） |

## 2. agent-service 新增工具（ToolRegistry 注册）

| 工具 | 数据源 | 关键行为 |
|---|---|---|
| `query_voucher` | voucher-service 券详情 | `rulesComplete=false` → "规则暂未录入"防编造；applicableScope 附店名 |
| `query_shop` | shop-service 商户详情 | `businessStatus` 由 openHours 推导（跨午夜/多段支持） |
| `search_shop_by_name` | shop-service 店名搜索 | 多候选 → SHOP_CANDIDATES 卡片不猜；唯一精确命中直返详情 |
| `kb_search` | rag-service 内部检索 | 来源标注"据商户资料"；故障/无资料完全降级（不计工具失败） |
| `query_my_orders`（增强） | order-service 既有接口 | 失败重试 1 次；size≤5 强制分页 + "下一页"指引；卡片补 voucherId |

## 3. Planner 模块（`com.hmdp.agent.planner`）

- `IntentClassifier`：7 类意图分类（lightModel + JSON mode），解析失败重试 2 次附错误说明，`m5_intent_parse_fail` 埋点
- `StructuredOutputParser`：JSON 容错提取 + schema 校验（纯逻辑）
- `PlannerService`：冲突检查（T3.5）→ 分类 → 澄清（T3.3，≤2 轮第 3 轮菜单）→ 7 类分流；`m5_intent` 埋点
- `FlowStateService`：Redis 澄清计数 / 冲突现场；flowState 持久化

## 4. 配置变更（application.yaml）

```yaml
glm.main-model: glm-5.3-flash   # 查询类回答生成（light-model 保持 glm-4-flash）
feign.client.config.rag-service.readTimeout: 5000
agent.planner.clarify-threshold: 0.6
agent.planner.max-clarify-rounds: 2
```

新增 SSE 卡片：`CLARIFY_MENU`（降级菜单）、`SHOP_CANDIDATES`（商户候选），协议见 D1.2 §2.3。

1. Docker 启动 MySQL/Redis/Nacos → 执行 `sql/phase3-voucher-fields.sql`
