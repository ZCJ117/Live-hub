## 1. 各项实现与验证方式

### D1 前端交互卡片层（P0，前端）
- **改动**：`agent-chat.js`（handleEvent 增加 `card` 分支 → `handleCard`；REFUND_CONFIRM 确认/取消→`POST /api/agent/chat/{id}/confirm`、TRANSFER_CONFIRM→`/transfer/confirm`、RATING→`/{id}/rating`（满意=5 直提、不满意=1 选标签）、CLARIFY_MENU 按钮点击走 `send(文案)`；`focusOrder` 改为携带 `context:{orderId}` 重建对话流）；`agent-chat.html`（四类卡片模板）；`css/agent-chat.css`（卡片样式）。**后端零改动**。
- **细节**：确认按钮点击即禁用防双击（幂等后端兜底）；确认接口的 SSE delta 与 HTTP 响应同文案，`appendAiOnce` 去重防双气泡；axios 统一 10s 超时（默认 2s 不够确认链路）。
- **验证**：`node --check` 通过；浏览器 E2E（待环境，见 §2 复现）：退款意图 → 卡片渲染 → 确认提交 → AI 气泡回执；订单点选 → 下一轮聚焦该订单（context 预注入，不依赖 LLM 解析）。

### D2 SSE 降级轮询（P0，前后端）
- **后端**：`SseSessionManager` 增加 `PollRoundCollector` 收集器挂载（send() 拦截：收集器/emitter 双通道，card 流水记录覆盖 poll 路径）；新增 `sse/PollRoundCollector`（delta 聚合 + card 列表 + done/error 完成信号）；`AgentChatController` 新增 `POST /agent/chat/poll`：入口与 `/agent/chat` 完全一致（复用 createOrReuse/getOwned + 安全链路），轮次仍在 sseExecutor 异步执行，请求线程仅 `await(3s)` 限时等待，超时返回 `{"partial":true}`（收集器保留，前端携 sessionId 空消息续拉）；message 空 + sessionId 有收集器 = 续拉在途轮次。**PRD 4.1：不在 Tomcat 工作线程同步阻塞等待 LLM**。
- **前端**：`openStream` → 建连时 `AbortController + setTimeout` 3s 竞速等 `session` 事件；失败/超时 → 提示"当前使用慢速通道" + 重试 SSE 1 次；再失败 → `pollMode=true`（提示条常驻），改调 `/agent/chat/poll`（续拉即 3s 节奏，服务端单次持有 3s），poll 响应 card 列表逐个走 `handleEvent` 同一分发。
- **验证**：`PollRoundCollectorTest` 3/3（聚合/完成/超时 partial）；浏览器 E2E（待环境）：断网/阻断 SSE 后降级轮询获得完整回答。

## 2. 端到端复现命令（需重启 agent-service 加载新代码；登录态 token 见 MS2-curl演示脚本）

```bash
# D2 后端 poll（SSE 降级通道；登录 token 换 $TK）
curl -s -X POST localhost:8081/agent/chat/poll -H "authorization: $TK" -H 'Content-Type: application/json' \
  -d '{"message":"你好"}'                       # 建连+欢迎语，返回 {partial:false, sessionId, text,...}
curl -s -X POST localhost:8081/agent/chat/poll -H "authorization: $TK" -H 'Content-Type: application/json' \
  -d "{\"sessionId\":$SID,\"message\":\"查我的订单\"}"   # 发消息；LLM 未完则 {partial:true}，用空 message 续拉

# D8 埋点上报
curl -s -X POST localhost:8081/agent/track -H "authorization: $TK" -H 'Content-Type: application/json' \
  -d '{"events":[{"eventName":"m5_first_token","sessionId":1,"props":{"latencyMs":800}}]}'

# D4 澄清第 3 轮：连续 3 轮低置信输入 → 第 3 轮 SSE 收到 card CLARIFY_MENU（选项含"转人工"）

# D6 等待期消息进移交包：确认转人工后继续 POST /agent/chat 发消息，然后
redis-cli -a 520117 GET "agent:transfer:$SID"   # history 数组尾部出现 user 消息 + assistant ack

# D9 工作台（先 Nacos/配置翻转 agent.transfer.seat-online=true 并重启）
curl -s "localhost:8081/agent/console/tickets?group=ORDER_GROUP" -H "authorization: $TK"
curl -s localhost:8081/agent/console/transfers -H "authorization: $TK"
curl -s localhost:8081/agent/console/transfers/$SID -H "authorization: $TK"
curl -s -X POST localhost:8081/agent/console/transfers/$SID/reply -H "authorization: $TK" \
  -H 'Content-Type: application/json' -d '{"text":"您好，人工客服为您处理"}'   # 用户端 SSE 收到 role=human 气泡
```

浏览器路径：`/agent-chat.html`（卡片/降级/复用提示/状态条合并）、`/agent-history.html` → 回放/工单详情、`/agent-console.html`（工作台）、`/info.html`（客服入口）。

## 3. 偏差与说明（评审留痕）
1. **D9 关闭工单**：文档原文"调既有 transition 接口"——既有 `PUT /agent/ticket/{ticketNo}/status` 含用户归属强绑定（FR-09 越权拦截是 MS2 退出标准，不可削弱），坐席关他人工单必被拒。故工作台走 `PUT /agent/console/tickets/{ticketNo}/status`（同一状态机核心 `doTransition`），用户侧接口零改动。
2. **D2 续拉契约**：文档未定义 partial 后续拉请求体；实现为 `{sessionId, message:""}`（空消息=续拉在途轮次），与"请求体与 /agent/chat 相同"兼容（message 空在 /agent/chat 语义是建连，poll 入口按是否有收集器区分）。
3. **D4（A3）与 D9（R9 冻结）**：按用户本次明确指令执行；D4 按 FR-03 原文（第 3 轮菜单），D9 演示级范围。
