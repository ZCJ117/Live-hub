## 4. 缺陷清单（分级）

### 严重（1 项，已修复）

**DEF-S1：ReAct 从不调用工具——FR-05/06/07 主路径断裂 + 伪查询幻觉**
- 相关模块：`ReActEngine.decide()`
- 复现：全新会话发送"我上周抢的券怎么还没到，查一下我的订单"（意图分类正确 ORDER_QUERY 0.9）
- 预期：调用 query_my_orders → tool_call/tool_result 事件 → 基于数据的回答 → agent_tool_call 留痕
- 实际：全程零工具调用（约 25 轮无一 tool 事件、审计 0 行），LLM 直接输出"暂未查询到您的订单数据…"伪查询回答
- 根因：decide() 的 LLM 请求只含 [system, 决策模板]，**不含对话历史也不含用户当前问题**——模型无从知晓诉求，永远选 `{"action":"ANSWER"}`。单测未发现：ReActEngineTest mock 了 LLM 返回，仅测循环 mechanics
- 影响范围：三大查询工具不可达、FR-04 可视化失效、审计失效、R1 幻觉防线失效、产品核心价值（查证而非瞎猜）不成立。**阻断上线级**
- 修复建议与落地：决策请求改为 baseMessages（system+历史）+ user(决策模板)，模板首行注入"用户当前问题"，并将"已能回答"改为条件化判定（数据为空/不足→必须先调工具）
- 修复后证据：tool_call/tool_result 事件到达、query_my_orders success=1（271ms）、审计落行、回答为真实数据（4 笔订单状态与 DB 一致）
