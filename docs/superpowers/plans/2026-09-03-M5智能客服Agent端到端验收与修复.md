### Task 0.3 按序启动服务栈

- [ ] 启动顺序（MS2 先例）：user(8086) → order(8084) → voucher(8083) → shop(8082) → social(8085) → agent(8088) → gateway(8081)。全部 `nohup mvn -pl <svc> spring-boot:run > .e2e/logs/<svc>.log 2>&1 &`。内存不足时优先砍 social（MQ 消费侧验证降级为 producer 日志/topic 查询），其次 shop。
- [ ] 就绪探活：逐服务 `curl -sf localhost:<port>/actuator/health`；Nacos 控制台确认注册
- [ ] 登录获取 token（MS2 脚本流程）：
  ```bash
  PHONE=13600001111   # 以实际库中存在用户为准
  curl -s -X POST "http://127.0.0.1:8081/user/code?phone=$PHONE"
  CODE=$(docker exec hmdp-redis redis-cli -a 520117 --no-auth-warning GET "login:code:$PHONE")
  TOKEN=$(curl -s -X POST "http://127.0.0.1:8081/user/login" -H "Content-Type: application/json" -d "{\"phone\":\"$PHONE\",\"code\":\"$CODE\"}" | 提取 token 字段)
  ```
- [ ] 建立工作目录 `.e2e/{logs,out,cases}`；GBK 坑：所有含中文的请求体用 python 写 UTF-8 文件再 `--data-binary @file`（参考 memory windows-gitbash-quirks）
- 验证：`curl -sN -X POST localhost:8081/agent/chat -H "Authorization: $TOKEN" -d '{"message":"你好"}' --max-time 15` 收到 session/delta/done 事件流。

## Phase 3 缺陷确认与修复（Subagent-Driven，TDD）

每个确认缺陷一个任务，模板固定：

- [ ] **Step 1 复现固化**：在 agent-service 测试套件中新增/修改最小失败测试（命名含缺陷 ID，如 `E2E_B3_dedup`），运行确认 FAIL，输出贴入缺陷记录
- [ ] **Step 2 修复**：最小改动（手术式，不重构邻近代码），修改行可逐一追溯到缺陷
- [ ] **Step 3 定向验证**：新测试 PASS + 所属 Cluster 相关既有测试 PASS；live 环境在则重放对应 E2E case 抓修复后证据
- [ ] **Step 4 审查**：spec 合规审查（对照 PRD 原文条款）+ 代码质量审查（对照 CLAUDE.md 三原则），修复 subagent 收口
- [ ] **Step 5 提交**：`fix(agent): <缺陷ID> <一句话>`；前端改动在嵌套仓内提交
- [ ] **Step 6 缺陷关闭登记**：更新 `.e2e/cases/defects.md`（修复前后对比：失败证据 vs 通过证据）
