# 微服务启动报错修复计划

## 问题分析

1. **Seata配置缺失**：缺少`service.vgroupMapping.hmdp-group`配置项，导致Seata客户端无法从Nacos获取服务映射
2. **Mapper扫描缺失**：微服务启动类缺少`@MapperScan`注解，导致MyBatis Plus无法扫描到Mapper接口
3. **Spring Cache配置缺失**：缺少CacheManager配置，导致依赖注入失败
4. **Seata配置不一致**：部分服务可能缺少完整的Seata配置

## 修复步骤

### 1. 修复Seata配置
在所有使用Seata的微服务（主要是order-service）的`application.yaml`中添加：
```yaml
seata:
  service:
    vgroup-mapping:
      hmdp-group: default
    grouplist:
      default: localhost:8091
```

### 2. 添加@MapperScan注解
在所有微服务的启动类上添加`@MapperScan`注解：
- OrderApplication: `@MapperScan("com.hmdp.order.mapper")`
- UserApplication: `@MapperScan("com.hmdp.user.mapper")`
- VoucherApplication: `@MapperScan("com.hmdp.voucher.mapper")`
- SocialApplication: `@MapperScan("com.hmdp.social.mapper")`
- ShopApplication: `@MapperScan("com.hmdp.shop.mapper")`

### 3. 配置Spring Cache
在所有微服务的`application.yaml`中添加Spring Cache配置，或者在启动类上添加`@EnableCaching`注解

### 4. 统一Seata配置
确保所有微服务都有完整的Seata配置（如果使用Seata）

## 修复文件列表

1. **order-service**
   - `src/main/java/com/hmdp/order/OrderApplication.java` - 添加@MapperScan
   - `src/main/resources/application.yaml` - 完善Seata配置

   - `src/main/resources/application.yaml` - 添加Cache配置

   - `src/main/java/com/hmdp/social/SocialApplication.java` - 添加@MapperScan

## 预期效果

修复后，所有微服务应该能够正常启动，不再出现：
- Seata配置缺失错误
- Mapper依赖注入失败
- CacheManager找不到的错误
- Feign客户端创建失败
