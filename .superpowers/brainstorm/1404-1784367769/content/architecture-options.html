三种架构方案对比

基础约束：GLM-5 · GLM Embedding · PgVector + tsvector + RRF · Apache Tika · RocketMQ 异步 · 商户级隔离

A

极简直连式

单一 Spring Boot 服务，Controller 直调 JDBC Template 操作 PgVector，无中间抽象层

Pros

  • 代码量最少（~15 个 Java 文件）
  • 部署简单，无额外依赖
  • 快速上线

Cons

  • 检索链路硬编码，难扩展
  • LLM/Embedding 切换需改代码
  • 不符合现有服务的分层规范
B

分层策略式 ⭐ 推荐

Controller → Service → Pipeline → Strategy，每层职责单一，策略模式封装检索链路和 LLM 调用

Pros

  • 符合项目现有分层规范
  • LLM/Embedding/检索策略可配置切换
  • 独立测试每个环节（分块/向量化/检索/生成）
  • 扩展开关重排序只需加一个策略实现

Cons

  • 类数量适中（~30 个 Java 文件）
  • 需定义清晰的接口契约
C

事件驱动 CQRS

读写模型分离，所有状态变更通过 RocketMQ 事件驱动，独立的 Embedding Worker

Pros

  • 极致解耦，写入和查询独立扩缩
  • 事件溯源可完整回放

Cons

  • 过度设计，点评业务规模不需要
  • 类数量多（~50+），维护成本高
  • 与项目现有简单风格不符
